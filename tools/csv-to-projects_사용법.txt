■ 프로젝트 실적 변환기 (csv-to-projects.html) — 사용법

  내부 실적 CSV(년도, 건물위치 — 상세 주소 포함)를 홈페이지용
  projects.json 으로 바꿔 주는 브라우저용 변환기입니다.

  - 설치가 필요 없습니다. csv-to-projects.html 을 더블클릭해 브라우저로
    열면 끝입니다. (배포된 홈페이지의 /tools/csv-to-projects.html 주소로
    열어도 됩니다)
  - 모든 처리는 브라우저 안(이 PC)에서만 일어나고 네트워크로 아무것도
    전송되지 않습니다. 인터넷이 끊긴 상태에서도 동작합니다.
  - 위치는 "서울 강남구"처럼 시/군/구 수준의 공개 지역명으로만 변환되며,
    상세 주소(도로명·지번·건물명)는 결과 파일에 어떤 경우에도 들어가지
    않습니다. 홈페이지에 필요한 4개 국어 고정 문구도 자동으로 포함됩니다.

■ 사용 순서

1. 원본 CSV 가 엑셀에서 열려 있으면 먼저 닫습니다.
   (열려 있으면 읽기가 실패할 수 있습니다)

2. csv-to-projects.html 을 열고, [① 원본 CSV 선택] 칸에 원본 CSV 를
   끌어다 놓거나 클릭해서 선택합니다.
   - 첫 줄 머리글에 "년도/연도" · "위치/주소"가 있으면 열을 자동으로
     찾습니다 (없으면 1·2열 사용).
   - 인코딩은 엑셀 저장 기본값(CP949), UTF-8 모두 자동 인식합니다.

3. [② 변환 결과] 의 숫자를 확인합니다.
   - 읽은 데이터 행 : 머리글을 뺀 전체 행 수
   - 변환된 실적   : 결과 파일에 포함되는 건수
   - 위치가 빈 행  : 위치 칸이 비어 있어 건너뛴 행
   - 지역 미인식   : 지역을 알아보지 못한 행 (아래 검토 목록에 표시)

4. 지역 미인식 행이 있으면, 검토 목록의 입력 칸에 "서울 강남구"처럼
   공개 지역명을 직접 적어 결과에 포함시킬 수 있습니다.
   - 입력하면 바로 옆에 인식 결과가 표시됩니다.
   - 비워 두면 그 행은 제외된 채 변환됩니다 (나머지 행에는 영향 없음).
   - 화면에 보이는 원본 주소는 이 화면에만 표시될 뿐, 결과 파일에는
     절대 들어가지 않습니다.

5. (선택) 사이트의 프로젝트 섹션 문구(제목·안내문)를 바꾼 적이 있다면,
   [① 원본 CSV 선택] 아래 고급 옵션에서 Pages CMS 로부터 내려받은 최신
   projects.json 을 불러와 그 문구를 유지하세요. 보통은 필요 없습니다.

6. [③ projects.json 내려받기] 를 누릅니다.
   (브라우저 다운로드 폴더에 projects.json 으로 저장됩니다)

7. Pages CMS → Media → [프로젝트 데이터] 에서 내려받은 파일을 올려
   기존 파일을 같은 이름으로 덮어씁니다.
   1~2분 뒤 홈페이지 프로젝트 섹션(지도/지구본)에서 반영을 확인합니다.
   (안 바뀌어 보이면 Ctrl+Shift+R 강력 새로고침)

■ 위치(지역명) 입력 형식 — 검토 목록에 적을 때

   적는 값                          결과
   ------------------------------  --------------------------------
   서울 강남구 / 서울특별시 강남구   강남구로 정확히 인식
   강북구                           시/도 없이 구 이름만 적어도 인식
   충남 당진 / 당진                 시 단위로 인식
   충청남도                         시/도 중심에 대략 표시
   필리핀 마닐라 / 베트남           국외 — 나라/도시명으로 인식
   국립중앙박물관 (건물명)          인식 안 됨 — 행정구역이 아님

   어떤 값을 적든 결과에는 지역 사전에 등록된 표준 지역명만 저장됩니다.

■ 주의사항

1. 원본 CSV(상세 주소가 든 파일)는 절대 GitHub 저장소나 Pages CMS 에
   올리지 마세요. 저장소가 public 이라 누구나 볼 수 있고, 한 번이라도
   커밋된 내용은 지워도 Git 이력에 영구히 남습니다. 원본은 저장소 폴더
   밖에 보관하세요. (이 변환기에 넣는 것은 안전합니다 — 파일이 PC 밖으로
   나가지 않습니다)

2. 업로드하는 파일 이름은 반드시 projects.json 이어야 합니다.
   홈페이지가 이 이름의 파일(content/downloads/projects.json)을 그대로
   읽습니다. 변환기가 만들어 주는 파일명을 바꾸지 마세요.

3. Pages CMS 에서는 "삭제 후 업로드"보다 "같은 이름으로 덮어쓰기"를
   권장합니다. 삭제와 업로드 사이에 사이트가 재배포되면 그 몇 분간
   홈페이지 전체 콘텐츠가 안 보일 수 있습니다. 덮어쓰기가 안 되고
   파일명이 바뀌어 올라가는 경우에만, 기존 파일을 지운 뒤 곧바로 다시
   올리세요.

4. 변환 결과는 기존 실적 목록을 통째로 대체합니다. CSV 에 전체 실적이
   다 들어 있는지 확인하고 돌리세요. 실수로 잘못 올렸다면 GitHub 커밋
   기록에서 이전 projects.json 을 복구할 수 있습니다.

5. 변환 규칙과 지역 사전은 사이트의 assets/js/projects.js ·
   assets/data/geo.json 을 그대로 내장한 사본입니다. 사이트 쪽을 고치면
   (예: geo.json 에 새 지역 추가) csv-to-projects.html 도 함께 갱신해야
   합니다 — 한쪽만 고치면 "변환은 됐는데 지도에 안 찍히는" 항목이
   생깁니다.

6. 특정 실적을 지우지 않고 잠시 숨기고 싶으면, 내려받은 projects.json
   에서 해당 항목의 "visible": true 를 false 로 바꿔 올리면 됩니다.

■ 자주 겪는 문제

- CSV 를 끌어다 놓아도 반응이 없거나 읽기 오류가 나요
  → 엑셀에서 그 파일이 열려 있는지 확인하고, 닫은 뒤 다시 시도하세요.

- 지역 미인식이 유독 많아요
  → 새로 생긴 지역(신설 구·군 등)이 지역 사전에 없는 경우입니다.
    저장소 assets/data/geo.json 에 항목을 추가한 뒤, 변환기도 함께
    갱신해 달라고 요청하세요.

- 업로드했는데 홈페이지가 그대로예요
  → 배포에 1~2분 걸립니다. 저장소 Actions 탭에서 배포 상태를 확인하고,
    브라우저에서 Ctrl+Shift+R 로 강력 새로고침하세요.
