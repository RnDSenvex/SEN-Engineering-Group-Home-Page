프로젝트 실적 변환기

원본 CSV(년도, 건물위치) → projects.json · Pages CMS [프로젝트 데이터] 업로드용

🔒 모든 처리는 이 PC의 브라우저 안에서만 일어나며, 어떤 파일도 네트워크로 전송되지 않습니다. 결과 파일의 위치 값에는 지역 사전에 등록된 시/군/구 수준 지역명만 들어갈 수 있어, 상세 주소(도로명·지번·건물명)는 어떤 경우에도 결과에 포함되지 않습니다.
📖 사용 설명서 — 사용 방법과 주의사항 (처음이라면 펼쳐서 읽어 주세요)

1. 이 도구가 하는 일

내부 실적 CSV(년도, 건물위치 — 상세 주소 포함)를 홈페이지용 projects.json으로 바꿔 줍니다. 위치는 "서울 강남구"처럼 시/군/구 수준의 공개 지역명으로만 변환되고, 상세 주소(도로명·지번·건물명)는 결과 파일에 어떤 경우에도 들어가지 않습니다. 홈페이지 프로젝트 섹션에 필요한 4개 국어 고정 문구(section/tabs/ui)도 자동으로 함께 담깁니다. 모든 처리는 이 브라우저 안에서만 일어나며 네트워크로 아무것도 전송되지 않으므로, 인터넷이 끊긴 상태에서도 동작합니다.

2. 사용 순서

  1. 원본 CSV가 엑셀에서 열려 있으면 먼저 닫습니다 (열려 있으면 읽기가 실패할 수 있습니다).
  2. 아래 ① 원본 CSV 선택에 파일을 끌어다 놓거나 클릭해서 선택합니다. 첫 줄 머리글에 "년도/연도"와 "위치/주소"가 있으면 열을 자동으로 찾고 (없으면 1·2열 사용), 인코딩(UTF-8 · CP949)도 자동 인식합니다.
  3. ② 변환 결과의 숫자를 확인합니다 — 읽은 데이터 행(머리글 제외 전체), 변환된 실적(결과에 포함), 위치가 빈 행(위치 칸이 비어 건너뜀), 지역 미인식(아래 검토 목록에 표시).
  4. 지역 미인식 행이 있으면 검토 목록의 입력 칸에 "서울 강남구"처럼 공개 지역명을 직접 적어 결과에 포함시킬 수 있습니다. 입력하면 바로 옆에 인식 결과가 표시되고, 비워 두면 그 행은 제외된 채 변환됩니다. (제외해도 나머지 행의 변환에는 영향이 없습니다)
  5. (선택) 사이트의 프로젝트 섹션 문구를 바꾼 적이 있다면, ①의 고급 옵션에서 Pages CMS로부터 내려받은 최신 projects.json을 불러와 그 문구를 유지하세요. 보통은 필요 없습니다.
  6. ③ projects.json 내려받기를 누릅니다 (브라우저 다운로드 폴더에 저장됩니다).
  7. Pages CMS → Media → 프로젝트 데이터에서 내려받은 파일을 올려 기존 파일을 같은 이름으로 덮어씁니다. 1~2분 뒤 홈페이지에서 반영을 확인합니다 (안 바뀌어 보이면 Ctrl+Shift+R 강력 새로고침).

3. 위치(지역명) 입력 형식 — 검토 목록에 적을 때

적는 값결과
서울 강남구 · 서울특별시 강남구강남구로 정확히 인식
강북구시/도 없이 구 이름만 적어도 인식
충남 당진 · 당진시 단위로 인식
충청남도시/도 중심에 대략 표시

어떤 값을 적든 결과에는 지역 사전에 등록된 표준 지역명만 저장됩니다. 새 지역이 자꾸 인식되지 않으면 저장소 assets/data/geo.json에 항목을 추가해야 합니다 (아래 주의사항 5번 참고).

4. 주의사항

  • 원본 CSV(상세 주소가 든 파일)는 절대 GitHub 저장소나 Pages CMS에 올리지 마세요. 저장소가 public이라 누구나 볼 수 있고, 한 번이라도 커밋된 내용은 지워도 Git 이력에 영구히 남습니다. 원본은 지금처럼 저장소 폴더 밖에 보관하세요. (이 도구에 넣는 것은 안전합니다 — 파일이 PC 밖으로 나가지 않습니다)
  • 업로드하는 파일 이름은 반드시 projects.json이어야 합니다 — 홈페이지가 이 이름의 파일을 그대로 읽습니다. 이 도구가 만들어 주는 파일명을 바꾸지 마세요.
  • Pages CMS에서는 삭제 후 업로드보다 같은 이름으로 덮어쓰기를 권장합니다. 삭제와 업로드 사이에 사이트가 재배포되면 그 몇 분간 홈페이지 전체 콘텐츠가 안 보일 수 있습니다. 덮어쓰기가 안 되고 파일명이 바뀌어 올라가는 경우에만, 기존 파일을 지운 뒤 곧바로 다시 올리세요.
  • 변환 결과는 기존 실적 목록을 통째로 대체합니다. CSV에 전체 실적이 다 들어 있는지 확인하고 돌리세요. 실수로 잘못 올렸다면 GitHub 커밋 기록에서 이전 projects.json을 복구할 수 있습니다.
  • 이 도구 안의 변환 규칙과 지역 사전은 사이트의 assets/js/projects.js · assets/data/geo.json을 그대로 내장한 사본입니다. 사이트 쪽을 고치면 이 파일도 함께 갱신해야 "변환은 됐는데 지도에 안 찍히는" 항목이 생기지 않습니다.
  • 특정 실적을 지우지 않고 잠시 숨기고 싶으면, 내려받은 projects.json에서 해당 항목의 "visible": true를 false로 바꿔 올리면 됩니다.

이 설명서는 같은 폴더의 csv-to-projects_사용법.txt로도 있습니다.

① 원본 CSV 선택

여기에 원본 CSV를 끌어다 놓거나, 클릭해서 선택하세요 첫 줄 머리글에 "년도/연도" · "위치/주소"가 있으면 자동 인식 (없으면 1·2열 사용)
인코딩은 UTF-8 · CP949(엑셀 저장 기본) 모두 자동 처리됩니다
고급 — 섹션 문구를 최신 projects.json에서 가져오기 (선택)

결과 파일에는 실적 목록 외에 섹션 제목·안내문(4개 국어 고정 문구)이 함께 들어가야 합니다. 기본으로는 이 도구에 내장된 현재 사이트 문구를 쓰므로 보통은 이 옵션이 필요 없습니다. 사이트 문구를 나중에 바꾼 적이 있다면, Pages CMS에서 내려받은 최신 projects.json을 여기에 불러오면 그 문구가 그대로 유지됩니다.

③ 내려받기 & 업로드

  1. Pages CMS → Media → 프로젝트 데이터로 이동합니다.
  2. 내려받은 projects.json을 올려 기존 파일을 같은 이름으로 덮어씁니다. (덮어쓰기가 안 되고 이름이 바뀌어 올라가면, 기존 파일을 지운 뒤 곧바로 다시 올리세요 — 파일명은 반드시 projects.json이어야 합니다)
  3. 1~2분 뒤 홈페이지 프로젝트 섹션(지도/지구본)에서 반영을 확인합니다.
사용 방법·주의사항은 맨 위 📖 사용 설명서 또는 같은 폴더의 csv-to-projects_사용법.txt를 참고하세요.
변환 규칙과 지역 사전은 사이트의 assets/js/projects.js · assets/data/geo.json과 동일합니다. 사이트 쪽을 고치면 이 파일도 함께 갱신하세요.
